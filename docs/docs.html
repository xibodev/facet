Make a Video With Your Agent

Facet is two parts packed together: the facet command-line tool, which runs stateless media operations, and the Facet bundle, which teaches your agent to use it. Your agentic CLI is the harness. It owns the model, tool calling, permissions, and memory; it plans the work and calls Facet's tools. You supply the idea or footage, approve consequential choices, and review the result.

Start with a simple request such as "Make a short explainer about how rain forms" or "Turn my screen recording into a concise walkthrough." You do not need to specify JSON, tool names, or a rigid production sequence.

Tool configuration, completed media generation, and editorial acceptance are separate checks.

Recommended Installation

Install Facet once for your user account, then wire it into the agentic CLIs you use: OpenCode, Codex, Claude Code, or GitHub Copilot CLI.

Facet 2.0.0 is unreleased. Until it is published, the commands below install the latest published release, v1.1.0, which still uses the 1.x per-project setup.

Run the command for your platform in a terminal:

# Windows (PowerShell)
irm https://xibodev.github.io/facet/install.ps1 | iex

# Linux / macOS
curl -fsSL https://xibodev.github.io/facet/install.sh | sh

The website bootstrap downloads and checksum-verifies the installer package, then launches the installer. The Unix one-liner requires an interactive terminal for its prompts.

The installer:

  • puts each runtime under ~/.facet/runtimes/<version>-<os>-<arch> and activates it as ~/.facet/current;
  • adds ~/.facet/current/bin to your user PATH; opt out with -NoPath on Windows or --no-path on Linux and macOS;
  • installs optional components into the runtime: remotion, piper, and hyperframes, with remotion,piper as the default; and
  • can wire your CLIs.

Installer actions are install, update, rollback, and uninstall, selected with -Action on Windows or --action on Linux and macOS.

  1. Run the installer and review the optional components.
  2. Wire the CLIs you use, during setup or later with facet wire.
  3. Run facet doctor to check dependencies.
  4. Start a new session in your CLI and ask it to use Facet.

Your CLI keeps its own models and authentication; Facet does not configure them.

Manual Installation

Download the installer ZIP from the release on GitHub, extract it, and run ./install.ps1 in PowerShell or bash ./install.sh from the extracted folder. Only the website bootstrap supports piping.

Production Runtime

Local editing and rendering do not require media-provider API keys. Edge TTS is built into Facet and uses a keyless network service; facet doctor does not test service reachability. Optional generation services may require separate credentials, account access, or credits.

  • FFmpeg and FFprobe: required for core media editing and inspection; facet doctor reports whether they are found.
  • Remotion (default component): animated compositions and rendered captions, with its browser and Node.js/npm dependencies.
  • Piper (default component): installed offline speech fallback with a pinned voice-model download.
  • HyperFrames (optional component): HTML-based video rendering, declared as using the network.
  • Edge TTS: preferred natural narration when network processing is acceptable; its client is built into Facet.
  • gflow: optional image/video generation through a separately supplied CLI.

Wire Your CLI

Wiring is your decision, like installing a skill or plugin. facet wire installs the Facet skills, and the creative persona agent where the CLI supports agents, into the CLI's native locations. It registers the facet MCP server through the CLI's own configuration. It never edits instruction files such as AGENTS.md or CLAUDE.md.

facet wire <cli>[,<cli>...]|all [--scope user|project] [--project DIR] [--dry-run]
facet wire --remove <cli>...
facet wire --status

<cli> is opencode, codex, claude, or copilot. --scope chooses user-level or project-level locations, --project names the project directory, and --dry-run shows the changes without making them. --status reports what is wired, and --remove unwires a CLI.

Upgrading from 1.x

Facet 1.x installed into each project. Facet 2.0 installs once per user, and wiring is a separate step.

  1. In each project that used the 1.x installer, run the v1.1.0 installer with --action uninstall (-Action uninstall on Windows). Download the v1.1.0 installer ZIP, extract it, and keep its installer/ directory beside the scripts; the v1.1.0 release lists its assets and SHA-256 checksums. The 1.x uninstall verifies ownership before it removes that project's managed Facet skill, state, and instruction section; modified and unmanaged content is kept.
  2. Install 2.0.
  3. Wire your CLIs with facet wire.

facet doctor reports leftover 1.x project files that would shadow the new skill.

Removed in 2.0: facet ui, facet-ui, and the browser preview; facet init; facet module and facet-module; per-project launchers (run-facet); per-project installer receipts and managed instruction sections; and the tool aliases audio_mixer and frame_sampler (use audio_mix and frame_sample).

Using Facet with Another Agent

Using a different agent? Facet's tools are served over MCP by facet mcp, and its skills are plain Markdown. Ask your agent to inspect this repository and adapt the skills and the MCP server registration to its own conventions. facet wire supports the four CLIs listed above; other integrations are community-adapted and may need additional setup.

Verify the Setup, Then Review the Work

Run facet doctor to inspect dependencies, runtimes, and tools; it also reports leftover 1.x project files that would shadow the new skill. Run facet wire --status to see what is wired. These checks do not test external provider access or establish editorial quality.

Review the actual video, audio, captions, and source material from your production before sharing it.

Facet App

The Facet app is withdrawn in 2.0. The 1.x browser preview did not work from the release installer and has been removed, together with facet ui and facet-ui. The app will return as Facet's own UI on top of Compa, built through Compa's public API. Until then, use Facet through a supported agentic CLI.

Use Your Agent in the Terminal

Open your wired CLI in a production folder and ask it to use Facet.

Use Facet to make a short explainer about how rain forms.

Use a separate directory for each production. In your agent conversation, try "Add captions to my recording" or "Make the narration slower and leave more time on the diagram." Give it the actual source file location when editing existing media.

Your CLI's permission settings decide which Facet tool calls need your approval. Facet declares each tool's effects (whether it may charge, uses the network, or makes external writes, and whether it is deterministic or read-only) but does not enforce consent. Configure your CLI so paid work and publication wait for your explicit consent. Unknown cost is not free.

Ask the agent to explain provider choices and costs before paid work, and to report errors without substituting placeholders. Number of turns, render duration, and final quality depend on the request and environment.

Choose a Production Pack

The bundle installs the core Facet skill and each of the following packs as its own skill. The Facet skill directs your agent to the relevant pack for the task. A pack supplies guidance and content, not proof that every referenced tool or provider is installed.

Explainer / @xibodev/facet-pack-explainer
Manifest: animated explainers, diagrams, charts, and text cards. Requires the Remotion runtime, browser, and usable narration route when speech is requested.
Cinematic / @xibodev/facet-pack-cinematic
Manifest: cinematic and documentary montages. Needs supplied or accessible source media with suitable rights; generated clips need configured providers.
Screen Demo / @xibodev/facet-pack-screendemo
Manifest: software walkthroughs and terminal scenes. Actual capture requires app access and recording/browser tooling; synthetic terminals must not be presented as real execution evidence.
Talking Head / @xibodev/facet-pack-talkinghead
Manifest: presenter edits and avatar workflows. Requires presenter footage or a separate avatar/lip-sync provider and consent. TTS alone does not generate a presenter.
Social / @xibodev/facet-pack-social
Manifest: vertical clips and podcast repurposing. Needs source media and accurate transcript/timing data for captions. Framing and moment selection need review; audience performance is not guaranteed.
Character Animation / @xibodev/facet-pack-animation
Manifest: rigs, pose libraries, and action timelines. Requires character assets, authoring, and a working renderer; no character-generation model is bundled by the pack.
Localization / @xibodev/facet-pack-localization
Manifest: translated voiceovers, subtitles, and dubbing. Requires source media, transcription/translation, and a target-language voice. Voice cloning or lip-sync needs separate provider support and consent; check translation and timing.

Optional gflow Integration

Facet's gflow_image and gflow_video tools can call a separately supplied compatible gflow CLI. The public Facet installer does not distribute that private provider dependency. Its help and error diagnostics explain the requirements of the provider you configure.

Setup or status success is not generation evidence. Quotas, credits, account eligibility, models, and service availability still apply. Facet does not promise zero-cost generation; unknown estimates or zero-valued generic metadata are not a billing guarantee.

Dependency, authentication, provider, timeout, and invalid-response errors should be investigated, not hidden by mock output. An explicit mock: true request creates test media; it is never proof of provider generation. A timed-out request may still be running remotely, so check before retrying.

Project Files Are the Durable Record

Facet stores no workflow state. Scripts, scene plans, narration, renders, and review outputs appear only when the corresponding work runs.

my-video/
  assets/             # supplied or acquired media
  artifacts/          # scripts/plans/reports when produced
  narration/          # generated or supplied voice tracks
  renders/            # video and review outputs when produced

Media directories and paths such as renders/final.mp4 are conventions, not a promise that installation creates a video. Tool results describe each artifact by path, media type, size, SHA-256, tool, and version. Over MCP, tool paths must stay inside the directory given by facet mcp --root; without it, they must stay inside the client's roots, or inside the working directory when the client supplies none.

Configuration can pin runtime paths in .facet.yaml or ~/.config/facet/config.yaml. Reopening a project preserves pinned configuration. Verify rendering from that production folder rather than relying on a successful run inside the source checkout.

Known Limitations

  • Installation is not acceptance. Local setup checks do not verify every workflow. Browser dependencies, fonts, pinned runtime paths, and provider access can still affect a production.
  • Pack guidance is broader than the executable registry. Some routes reference optional tools, models, transcription, or browser integrations not supplied by the native CLI. Check the installed tool and its actual implementation before relying on it.
  • Network services are conditional. Edge TTS is keyless but network-dependent. Other providers may need credentials and payment; model availability and account limits can change.
  • Consent is enforced by your CLI, not by Facet. Facet declares each tool's effects; your CLI's permission settings and the Facet guidance decide when you are asked.
  • The Facet app is withdrawn. Use Facet through a supported agentic CLI.
  • Automated review is partial. Technical media checks and sampled frames do not establish factual accuracy, language quality, consent, asset rights, or creative quality. Watch and listen to the output.

These pages do not certify a release or promise a finished video in a fixed number of turns or minutes.

Technical Reference

Most users can stay with natural-language prompts. Integrators should inspect the installed CLI and source contracts rather than copy an assumed universal scene payload.

request.json must contain the fields accepted by the selected tool and operation. Discover the tool catalog from the installed build rather than trusting a fixed count.
