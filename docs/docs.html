Make a Video With Your Agent

Facet combines production instructions, a Go media toolbox, and a local browser Studio. Your coding agent plans the work and invokes tools. You supply the idea or footage, approve consequential choices, and review the result.

Start with a simple request such as "Make a short explainer about how rain forms" or "Turn my screen recording into a concise walkthrough." You do not need to specify JSON, tool names, or a rigid production sequence.

Install the source bundle and authenticate an agent before trying either workflow. Tool configuration, completed media generation, and editorial acceptance are separate checks.

Install From a Complete Checkout

Install Git, Go 1.25+, Node.js 18+ with npm, and FFmpeg and FFprobe on PATH. Linux/macOS also require Bash and tar. Browser-based rendering requires a supported Chromium browser, system libraries, and fonts.

The source scripts build both facet and facet-ui, copy the production bundle, and run npm ci for the installed Remotion composer. Go modules and npm dependencies may need network access.

Windows

git clone https://github.com/xibodev/facet.git
pwsh -File ./facet/install.ps1 -NonInteractive

Default locations are %USERPROFILE%/.facet/bin and %USERPROFILE%/.facet/bundle. The installer updates the user PATH; reopen your terminal because the child pwsh process cannot update its parent's environment.

  • -NonInteractive suppresses prompts, not side effects. Desktop and Start Menu shortcuts are still created by default.
  • -NoShortcuts skips shortcuts; -NoPath leaves PATH unchanged. With -NoPath, invoke the installed executable by its full path.
  • Existing shortcuts are preserved by default. Add -UpdateShortcuts when installing into a fresh destination to retarget only recognized Facet links (the current home default, legacy LocalAppData default, or selected install directory, with no arguments). Custom targets or arguments are always preserved and must be edited manually. This flag cannot be combined with -NoShortcuts or -Isolated. After a side-by-side install, launch the new Studio directly with & 'C:\path\to\new\bin\facet-ui.exe' if the old shortcut was preserved; rerunning into the occupied destination is still refused.
  • -Scope on-demand is the default: no global agent skills are changed. -Scope global registers the core skill for Claude Code and OpenCode only, preserving existing skills. Packs stay project-local.
  • -InstallDir selects the binary directory, with a sibling bundle directory. The installer refuses to overwrite existing binaries or a bundle; use a fresh destination rather than deleting a working installation.
  • -Isolated is for isolated installs/tests and requires explicit -HomeDir, -InstallDir, -NoPath, -NoShortcuts, and on-demand scope. The home must differ from your real profile.

For the complete flag contract, read install.ps1.

Linux / macOS

git clone https://github.com/xibodev/facet.git
bash ./facet/install.sh
export PATH="$HOME/.facet/bin:$PATH"

install.sh installs under ~/.facet without changing shell profiles, global agent skills, or custom Facet configuration. Add the PATH export to your shell profile for future terminals. The Bash installer writes into its fixed install location; it is not the Windows fresh-destination installer.

What Is Installed

.facet/
  bin/                 # facet and facet-ui (Windows: .exe)
  bundle/
    skills/
    packs/
    pipeline_defs/
    schemas/
    styles/
    remotion-composer/  # source, lockfile, installed npm dependencies

Both scripts resolve source relative to their own file and can be called by absolute path from another directory. They do not download or clone source for you.

Not supported as full installs: piping a remote script into a shell, installing the Go CLI alone with go install, or assuming npm/npx will deliver native binaries. npm provides launchers and content; install native Facet from source first. There is no zero-install guarantee.

npm launchers check an existing FACET_BIN executable override first, then package-local binaries, then ~/.facet/bin. On Windows, the legacy %LOCALAPPDATA%/Programs/Facet/bin location is a final fallback. Set FACET_BIN to the full native executable path for the command being launched (CLI or Studio), not a directory; a missing override falls back to normal discovery. Launchers never search PATH for themselves.

Check the Host, Then Test the Work

facet version
facet doctor

Read the diagnostic results from your own machine. Resolve missing FFmpeg, FFprobe, Node, composer, or agent dependencies before producing. There is deliberately no sample "all ready" output here.

Install and authenticate Claude Code, OpenCode, Codex, or GitHub Copilot separately. An executable on PATH is not proof that the account, selected model, or provider is usable. Facet does not supply model access.

doctor does not produce a video or certify a release. Verify a real render from your intended production directory, inspect the file, and review it visually and audibly.

Use Facet Studio

facet ui

Open http://localhost:8787 if the browser does not open automatically. Use facet ui --port 8788 --no-open to choose another port without opening a browser. Use --dir /absolute/path/to/productions to set the working/project root.

  1. Create a production or open an existing folder. The new-production form asks for a Production Name, Folder Slug, Agent Engine, and Production Packs. Check the location preview before selecting Create & Launch.
  2. Select a usable engine. Studio checks which CLIs are available. Install and authenticate your choice outside Studio; a listed engine can still fail on login, quota, or model access.
  3. Send your request in chat. For example: "Make a short introduction to our project using the logo in assets." The agent's activity appears while it works. Read errors instead of treating an idle chat as success.
  4. Review actual artifacts. As project files appear, inspect the script, narration, review images/report, and available video. Play the video and use its download action when a render exists. A newly created project has no finished video.
  5. Ask for a revision. Keep the same project selected and say what should change. Switching projects or engines separates the conversation context.

Reload and Session Boundaries

Reselecting the same project retains its active session. Reloading the same browser tab can restore a completed conversation within the current Studio process lifetime.

It does not restore an in-flight turn, replay earlier activity, or recover a chat after restarting Studio. A different project or engine starts separate context. Project files remain on disk; a new conversation can inspect those files to reconstruct the work.

If the connection fails, check the agent error, restart the session as directed by Studio, and inspect existing outputs before retrying. A provider job may still be running after a timeout.

Studio binds to loopback. It is not a public or multi-user deployment; ordinary Docker -p publishing is insufficient to expose that listener.

Use Your Agent in the Terminal

facet init my-video --engine opencode

This initializes a production folder, projects the core and Explainer skills, and launches OpenCode there. Replace opencode with claude, codex, or copilot. Without an engine flag, the CLI defaults to Claude Code.

To create the files without launching an agent:

facet init my-video --engine opencode --no-launch

Use a separate directory for each production. In your agent conversation, try "Add captions to my recording" or "Make the narration slower and leave more time on the diagram." Give it the actual source file location when editing existing media.

Ask the agent to explain provider choices and costs before paid work, and to report errors without substituting placeholders. Number of turns, render duration, and final quality depend on the request and environment.

Choose a Production Pack

The source bundle contains the following packs. Studio's form lists installed packs; basic facet init selects Explainer. A pack supplies guidance and content, not proof that every referenced tool or provider is installed.

Explainer / @xibodev/facet-pack-explainer
Manifest: animated explainers, diagrams, charts, and text cards. Requires the Remotion runtime, browser, and usable narration route when speech is requested.
Cinematic / @xibodev/facet-pack-cinematic
Manifest: cinematic and documentary montages. Needs supplied or accessible source media with suitable rights; generated clips need configured providers.
Screen Demo / @xibodev/facet-pack-screendemo
Manifest: software walkthroughs and terminal scenes. Actual capture requires app access and recording/browser tooling; synthetic terminals must not be presented as real execution evidence.
Talking Head / @xibodev/facet-pack-talkinghead
Manifest: presenter edits and avatar workflows. Requires presenter footage or a separate avatar/lip-sync provider and consent. TTS alone does not generate a presenter.
Social / @xibodev/facet-pack-social
Manifest: vertical clips and podcast repurposing. Needs source media and accurate transcript/timing data for captions. Framing and moment selection need review; audience performance is not guaranteed.
Character Animation / @xibodev/facet-pack-animation
Manifest: rigs, pose libraries, and action timelines. Requires character assets, authoring, and a working renderer; no character-generation model is bundled by the pack.
Localization / @xibodev/facet-pack-localization
Manifest: translated voiceovers, subtitles, and dubbing. Requires source media, transcription/translation, and a target-language voice. Voice cloning or lip-sync needs separate provider support and consent; check translation and timing.

Google Flow Is a Separate Prerequisite

Facet's gflow_image and gflow_video tools call the standalone gflow CLI. Facet does not install or authenticate that tool, its extension, or a Google account.

  1. Follow the gflow project's installation instructions and put the standalone gflow executable on PATH.
  2. Install its Chrome extension and grant the extension the required site permissions for labs.google.
  3. Open Google Flow in that Chrome profile and log in with an account that has access. Keep the browser/extension connection available as required by gflow.
  4. Use the CLI's setup/status diagnostics to check the connection. Then, only with approval for any account credits or charges, test real generation and inspect the returned local file.

Setup or status success is not generation evidence. Quotas, credits, account eligibility, models, and service availability still apply. Facet does not promise zero-cost generation; unknown estimates or zero-valued generic metadata are not a billing guarantee.

Dependency, authentication, provider, timeout, and invalid-response errors should be investigated, not hidden by mock output. An explicit mock: true request creates test media; it is never proof of provider generation. A timed-out request may still be running remotely, so check before retrying.

Project Files Are the Durable Record

Initialization creates project directories and configuration. Scripts, scene plans, narration, renders, and review outputs appear only when the corresponding work runs. Their existence is not a verdict on quality.

my-video/
  assets/             # supplied or acquired media
  artifacts/          # initial brief, later scripts/plans/reports
  narration/          # generated or supplied voice tracks
  renders/            # video and review outputs when produced
  .facet/             # local ownership metadata
  .facet.yaml         # project configuration
  facet.lock.json     # engine and selected pack record

Agent-specific skill projections are also created, for example .opencode/skills/. Paths such as renders/final.mp4 are conventions, not a promise that initialization creates a video.

Configuration can pin runtime paths in .facet.yaml or ~/.config/facet/config.yaml. Unpinned discovery looks near the working directory and executable, then in the user bundle. Reopening a project preserves pinned configuration. Verify rendering from that production folder rather than relying on a successful run inside the source checkout.

Known Limitations

  • Installation is not acceptance. The installers do not verify a completed render. Browser dependencies, fonts, pinned runtime paths, and provider access can still fail.
  • Pack guidance is broader than the executable registry. Some routes reference optional tools, models, transcription, or browser integrations not supplied by the native CLI. Check the installed tool and its actual implementation before relying on it.
  • Network services are conditional. Edge TTS is keyless but network-dependent. Other providers may need credentials and payment; model availability and account limits can change.
  • Studio is not durable workflow hosting. Completed-session reload is limited to the same tab and current server lifetime. No in-flight recovery, transcript replay, or server-restart continuation is provided.
  • Automated review is partial. Technical media checks and sampled frames do not establish factual accuracy, language quality, consent, asset rights, or creative quality. Watch and listen to the output.

These pages do not certify a release or promise a finished video in a fixed number of turns or minutes.

Technical Reference

Most users can stay with natural-language prompts. Integrators should inspect the installed CLI and source contracts rather than copy an assumed universal scene payload.

Expand CLI Commands and Source Schemas 
facet help
facet init --help
facet ui --help
facet tools list
facet tools describe video_compose
facet tools describe output_review
facet tools estimate <tool-name> --input request.json
facet tools run <tool-name> --input request.json

request.json must contain the fields accepted by the selected tool and operation. Discover the tool catalog from the installed build rather than trusting a fixed count. Registry descriptions and standalone schemas cover different surfaces and can lag implementations.

  • CLI commands and flags
  • Tool registry, aliases, and request descriptions
  • Composition request handling and renderer invocation
  • Remotion composition registration, default props, and themes
  • Explainer scene types and rendering
  • Artifact JSON schemas and standalone tool JSON schemas
  • Technical output review implementation
  • Google Flow request validation and error handling
  • Core producer guidance and pipeline definitions

Links point to the source branch, which may differ from your installation. Use the matching checkout revision when debugging. No single page here claims complete API coverage.
